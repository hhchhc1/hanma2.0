🧵 改进一：POSIX 标准化线程模型

❌ 改前问题

  • 68 个文件散布裸 FreeRTOS API
  • 换 RTOS = 重写全部业务代码
  • 与 OpenVela 社区接口不兼容

✅ 改后效果

  • 全部封装为标准 POSIX 接口
  • 上层应用与 RTOS 完全解耦
  • 只需替换底层 4 个头文件即可移植
// 改前：FreeRTOS 裸 API xTaskCreate(func, "dht22", 4096, NULL, 5, NULL); // 改后：POSIX 标准接口 posix::task_create({"dht22", 4096, 5, -1}, func);
main/posix_compat/ ├── posix_event.h — 事件组标准接口 ├── posix_queue.h — 消息队列标准接口 ├── posix_task.h — 任务创建标准接口 └── posix_timer.h — 定时器标准接口
💬 一句话：把 68 个电器的插头全换成国标，以后搬家（换系统）只要换墙上插座，电器不用动。

层级机制效果

🌐 改进四：mDNS 自动服务发现

❌ 原问题

  • P4 IP 由 DHCP 动态分配
  • 每 2-3 天 IP 就变化
  • C3 固件硬编码 IP 192.168.1.253
  • 每次 IP 变 = 改代码 + 重新烧录
  • 完全不可接受的维护负担

✅ 解决方案

P4 广播
xiaozhi.local
↔
C3 mDNS
自动解析
→ 零配置 · 永久免维护
💬 一句话：P4 给自己起了个永不变的名字（微信号），C3 每次开机喊一声就能找到它，不管它 IP 号码怎么变。
